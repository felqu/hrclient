# HR Client: Telegram parser

HTTP API парсинга запускается из корня проекта:

```bash
.venv/bin/python -m pip install 'duckdb>=1.1,<2' 'openpyxl>=3.1,<4'
cd backend
../.venv/bin/python -m uvicorn app.api.parse_api:app --port 8000
```

Парсер также использует установленные FastAPI, tgscraper, python-dotenv,
openai и zai-sdk; для Telethon нужны Telegram API credentials.
Страница парсинга: `http://localhost:8000/parse.html`, дашборд: `http://localhost:8000/`.
При прямом запуске `python -m app.api.parse_api` порт — `8090`; страницы автоматически
используют API на своём адресе. Docker-фронтенд на `5173` обращается к API на `8000`.
Для другого отдельного фронтенда задайте `window.HR_CLIENT_API_URL` перед `api.js`.

## Логи пайплайна

Лог создаётся автоматически в `backend/logs/pipeline.log` (UTF-8).
Путь переопределяется переменной `PARSE_LOG_PATH`. Каждый запуск помечен `run_id`,
по которому можно связать этапы парсинга и сохранения.

Записываются параметры запуска, получение сообщений по каналам, полный текст каждого
сообщения, причины пропуска, текст запроса к LLM (до 8000 символов), исходный ответ LLM,
ошибки валидации, структурированная вакансия, запись в DuckDB, итоговые количества,
чтение базы и создание XLSX. Ошибки включают traceback. Ключи API и настройки
авторизации в лог не передаются.

При размере 10 МБ файл ротируется; сохраняются три предыдущих файла.
Логи и база исключены из Git.

## Сохранение вакансий

Оба маршрута запуска (`POST /api/v1/parse` и `POST /api/v1/vacancies/import`)
сохраняют извлечённые вакансии в `backend/data/vacancies.duckdb`, таблица `vacancies`.
База создаётся автоматически. Другой путь можно задать переменной `VACANCIES_DB_PATH`
(относительный путь считается от рабочего каталога сервера).

Вакансии накапливаются и доступны после перезапуска. Повторное сообщение обновляет
запись по каналу и ID сообщения; формы `@name`, `name` и `https://t.me/name`
считаются одним каналом. Полная модель хранится в JSON-колонке `payload`, а название,
компания, канал, ID сообщения и дата публикации доступны отдельными SQL-колонками.
Пустой результат или сбой канала не удаляет сохранённые вакансии.

- `GET /api/v1/vacancies` — вся коллекция в формате дашборда.
- `GET /api/v1/vacancies/parsed` — вся коллекция в полном формате `JobVacancy`.
- `GET /api/v1/vacancies/export.xlsx` — скачивание всей коллекции в XLSX.

Кнопка **«Экспорт в XLSX»** есть на дашборде и странице парсинга. Файл содержит
условия работы, зарплату, требования, контакты, ссылки и исходные тексты. В первой
строке включены фильтры, заголовки закреплены. Даты и суммы экспортируются как
даты и числа, текст сообщений — как текст, даже если начинается с `=`.
Excel ограничивает текст одной ячейки 32 767 символами; полный текст остаётся в DuckDB.

Запускайте этот API с одним worker: операции базы сериализуются внутри процесса,
DuckDB не поддерживает запись в один файл из нескольких процессов.

## Проверка

Из корня проекта:

```bash
PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests -v
node --test frontend/tests/export.test.cjs
```

Тесты используют временные базы и подменяют TelegramGateway, не отправляя запросы
в Telegram или LLM.
